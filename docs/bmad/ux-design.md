# UX 设计文档：摇骰子聚会助手（微信小程序）

- **项目：** 摇骰子聚会助手
- **日期：** 2026-03-11
- **设计：** BMAD UX Designer（AI）
- **版本：** 1.0

---

## 1. 设计概览

### 1.1 项目摘要

这是一款用于线下聚会的“叫骰”房间小程序：玩家围坐，按现实座位顺/逆时针轮转完成 **摇骰 → 叫骰 → 开牌 → 结算**。核心体验目标是：**高级感（视觉与质感）、丝滑（交互与动效）、低歧义（规则与可见性明确）、不怕断网（可恢复与防卡死）**。

### 1.2 设计目标（P0）

1. **看起来像正式产品**：统一的中式轻奢牌桌语言（木纹+金色点缀+米黄桌布），减少“开发调试感”。
2. **操作更少更对**：根据阶段动态呈现关键动作，避免按钮堆叠与误触。
3. **公平可解释**：私密骰面、等待者权限、开牌胜负与“谁输谁先”在 UI 上可被理解与复核。
4. **AI-only 可回归**：`testMode` 下具备“可重复、可复算、可对照”的验证路径（固定种子/注入骰面/语音 mock）。

### 1.3 成功指标（可验收）

- 新用户从大厅到“成功开局” ≤ 30 秒（含排位）。
- 房间内主要动作（摇骰/叫骰/开牌）误触率显著降低：按钮数减少且仅在可操作时可点。
- 等待者在对局中“看得懂但不能干预”：能看进度与公开信息，永远看不到私密骰面。
- 小屏机型（宽 320px 等价）无关键遮挡；可触控区域 ≥ 44px。

### 1.4 目标设备

- 微信小程序（竖屏为主）
- iOS/Android 常见机型（含刘海/底部安全区）

## 2. 用户画像（Personas）

### 2.1 房主（组织者/主持）

- 目标：快速建房、分座位、开局、掌控节奏；处理“中途加入等待者”。
- 痛点：排位不直观、按钮多易误触、断线重连后不确定房间状态。
- 关键能力：可配置房间规则、排位/交换座位、开始/下一局。

### 2.2 玩家（对局参与者）

- 目标：快速看懂“轮到谁”、自己能做什么；叫骰与开牌干净利落。
- 痛点：叫骰输入麻烦、语音与结构化不同步、开牌结果不够清晰。
- 关键能力：摇骰、叫骰（含语音确认）、开牌（仅上一手）。

### 2.3 等待者（旁观者）

- 目标：能进入房间、看进度与聊天/语音；等下一局再入座。
- 痛点：不知道为何不能操作、看不到关键结果、被误认为“掉线玩家”。
- 关键能力：旁观公开信息（玩家列表/当前叫骰/开牌后全局骰面），不可见私密骰面。

## 3. 核心交互原则（高级感 + 丝滑）

1. **阶段驱动 UI（Phase-driven UI）**：同一位置只放当前阶段的关键动作，其他动作收纳至“更多”或次级入口。
2. **底部 Dock + 底部抽屉（Bottom Sheet）**：主要操作集中在底部，复杂输入（叫骰、排位）使用抽屉承载，避免页面跳转。
3. **明确的反馈链**：按下 → 轻触震动 → 状态变化（loading/disabled）→ 成功动画/提示。
4. **信息层级清晰**：
   - 顶部：房间号、网络状态、更多
   - 中央：牌桌、当前回合与上一手、公开结果
   - 底部：当前能做的事（按钮少且大）

## 4. 关键页面与状态（Wireframes + 说明）

> 说明：以下为 P0 页面与关键状态；视觉采用“木纹边框 + 米黄桌布 + 金色描边”的一致语言。

### 4.1 大厅（Lobby）

**目的：** 配置昵称与服务器地址，选择创建/加入/继续进入。

**关键状态：**
- 未同意隐私：弹出协议层（可去隐私/用户协议页）
- 已有会话：出现“继续进入/清空会话”

### 4.2 创建房间（Create Room）

**目的：** 房主选择配置并进入房间。

**配置控件：**
- 出手方向（必选，按钮组选中态）
- 通配1 开关（解释 tooltip：开启=1可通配；叫过1后失效）
- 起叫最小数量（数字输入/步进器）
- 多人开牌：置灰占位（标注“后续开放”）

### 4.3 房间（Room）— 准备阶段（ready）

**目的：** 房主排位、开始；其他人等待。

**UI：**
- 顶部：房间号/网络状态/更多
- 圆桌：玩家按座位环形排列，展示座位号与昵称缩写
- 次级条：`房主排位`（仅房主且首局开局前）/ `等待X`（存在等待者）
- 底部 Dock：显示 `语音`、`开始`（首局房主/后续局失败方）、`历史/语音列表` 等

### 4.4 房间 — 摇骰阶段（diceRolling）

**目的：** 发起者开始新一局后，全体对局玩家完成本局摇骰与确认。

**UI：**
- 圆桌：当前操作者边框高亮
- 中央：仅自己显示自己的骰面；其他人显示“已摇/未摇”状态（不展示点数）
- 底部 Dock：所有对局玩家初始主按钮为 `摇一摇`；摇出骰面后切为 `OK`；确认后切为 disabled `等待`；全部确认后自动进入 `calling`

### 4.5 房间 — 叫骰阶段（calling）

**目的：** 当前玩家叫骰或开牌（仅上一手）。

**关键交互：叫骰抽屉（Call Sheet）**
- 显示：上一手 `X个Y`、本房间 `minOpeningCount`、通配1是否开启
- 输入：数量/点数步进器（大触控区），提供“填入最小合法加注”
- 提交：`确认叫骰`（提交前二次确认可选）

**开牌：**
- 仅当存在上一手时显示/可点 `开牌`
- 当前叫牌人：隐藏右下角主按钮并显示叫牌面板
- 非当前叫牌人：保留 disabled `等待` 按钮，点击无业务响应

### 4.6 房间 — 开牌/结算（opening/ended）

**目的：** 展示全局骰面与胜负，并由上一局失败方开始下一局。

**UI：**
- 中央：全局骰面摘要（座位+昵称缩写+5骰）
- 文案：胜者/败者、比较口径（`totalCount(Y)` 与 `X`）
- 底部 Dock：仅上一局失败方出现 `开始`；其他玩家显示 disabled `等待`

### 4.7 房主排位抽屉（Seating Sheet）

**目的：** 让房主把现实座位映射到 seatIndex，支持交换。

**交互：**
- 先“选玩家”→再点座位；若座位已占用则“自动交换”
- 显示座位列表 1..8 与当前占用者
- 开局后入口消失/置灰，并提示“已锁定”

## 5. 组件规格（Component Specs）

### 5.1 顶部信息栏（Top Bar）

- 高度：视觉约 10%
- 左：用户头像缩写 + 房间号 chip
- 中：网络状态 chip（绿/黄/红 + 文案）
- 右：更多（按钮）
- 交互：网络 chip 可点击触发重连/提示（已有实现）

### 5.2 圆桌与座位（Table + Seats）

- 玩家头像：圆形，金色/红色/紫色等边框态区分（不可只依赖颜色：同步文案/图标/标签）
- 座位标签：`X号` + 昵称（2字）
- 气泡：显示当前叫骰 `X个Y`，在圆内指向头像

### 5.3 底部 Dock（主操作区）

- 只展示“当前能做的事”，并确保按钮高度 ≥ 88rpx（触控友好）
- 关键按钮：
  - 语音（按住录音）
  - 主操作（摇骰/叫骰/开牌/开始/下一局）按阶段切换
  - 次操作（历史/语音列表/更多）

### 5.4 抽屉（Bottom Sheet）

- 用于：叫骰输入、排位
- 动效：上滑 240ms（ease-out），遮罩 0.6 alpha
- 关闭：右上角关闭 + 点击遮罩关闭（关键输入场景可二次确认）

---

## 6. 可访问性与可用性（WCAG 对齐）

- 触控目标：≥ 44px（约 ≥ 88rpx），“小按钮”也要保证可点区域。
- 对比度：正文文字 ≥ 4.5:1；非文字 UI（边框/图标）≥ 3:1。
- 不只靠颜色表达：当前操作者/离线/房主等，除颜色外增加标签或图标。
- 语音：录音状态必须有显著反馈（颜色 + 文案），失败态可恢复。

---

## 7. 响应式与适配

- 竖屏优先；考虑刘海与底部安全区：所有底部 Dock 与抽屉内边距包含 `safe-area-inset-bottom`。
- 小屏（等价 320px）：
  - 底部 Dock 支持横向滚动或减少同时出现按钮数
  - 文案缩短（昵称 2 字、房间号短格式）

---

## 8. 设计 Token（落地到 WXSS）

> P0 建议引入轻量 Token（不强依赖 CSS 变量），以 class 复用为主。

### 8.1 颜色

- 背景（夜色）：`#0f0c0b`
- 木纹深色：`#1d1109` / `#2c180d`
- 金色主色：`#f7d788` / `#c88c40`
- 桌布米黄：`#f6efdf`（搭配暗金纹理/渐变）
- 语义色：成功 `#38bf92`，警告 `#f8bf56`，错误 `#ea7f7f`

### 8.2 字体与间距

- 基准字号：26–28rpx；重要数字/标题：32–42rpx
- 圆角：14rpx（按钮）/ 22–24rpx（卡片/抽屉）
- 阴影：主卡片 `0 18rpx 40rpx rgba(0,0,0,0.35)`（克制使用）

### 8.3 动效（Motion）

- 快速反馈：120ms（pressed/hover）
- 抽屉：240–320ms（ease-out）
- 座位重排：220–280ms（ease）
- 触感：关键动作 `wx.vibrateShort({type:'light'})`

---

## 9. 开发交付说明（Handoff Notes）

1. **先做结构再做皮肤**：先把底部 Dock 与抽屉结构确定，再统一样式与动效。
2. **阶段驱动按钮可见性**：减少常驻按钮数量，避免“7个按钮堆叠”带来的廉价感与误触。
3. **统一样式来源**：建议把常用按钮/卡片/抽屉样式抽到 `miniprogram/styles/*`，各页只做布局。
4. **性能注意**：避免高频 setData；座位坐标预计算；动画用 CSS transition 为主。
