# 摇骰子小程序：上线检查清单

> 目标：在不改动房间主链路的前提下，用最少步骤确认当前版本具备提包与上线条件。

## 1. 产品口径

- [ ] 创建房间页明确为“固定 8 杯位房间”
- [ ] 页面、规则、协议、帮助文案一致
- [ ] 当前版本不再对外描述聊天和语音能力
- [ ] “联系邮箱”可见且可复制：`569500252@qq.com`

## 2. 账号与资料

- [ ] 首次进入大厅可先浏览，不强制立即登录
- [ ] 点击创建房间 / 加入房间 / 继续房间后才弹登录抽屉
- [ ] 登录抽屉默认不勾选协议
- [ ] 勾选《用户协议》《隐私政策》后才允许登录
- [ ] 微信登录可正常进入大厅
- [ ] “我的”页修改昵称可成功保存
- [ ] 昵称校验生效：
  - [ ] 1-5 个字符可通过
  - [ ] 空昵称被拦截
  - [ ] 广告/联系方式/违禁词被拦截
- [ ] 退出登录后重新进入，不残留旧账号态

## 3. 房间主链路

- [ ] 创建房间成功
- [ ] 分享房间可正常拉起加入
- [ ] 第二台设备可加入房间
- [ ] 房主排位可正常交换座位
- [ ] 结算后房主仍可重新打开排位并调整座位
- [ ] 对局中加入的玩家先进入等待，结算后可由房主安排入座
- [ ] 可正常开始一局
- [ ] 摇骰 -> OK -> 叫牌 -> 开牌 -> 结算 -> 再来一局 全链路通过
- [ ] 8 人上限逻辑正常
- [ ] 对局中掉线后可恢复
- [ ] 对局中主动离开不会卡死当前轮次
- [ ] 只剩 1 名有效玩家时当前局回到 ready，不写入结算历史
- [ ] 输家离线/已退出时，房主可接管下一局开始

## 4. 页面与协议

- [ ] 隐私政策可打开
- [ ] 用户协议可打开
- [ ] 协议内容与当前能力一致
- [ ] 首页不再出现“点击登录即表示同意”类默认同意文案
- [ ] 大厅登录抽屉是勾选式同意，不默认勾选
- [ ] 分享直进房间抽屉保留改昵称，并提供“返回大厅 / 暂不进入”
- [ ] 首次进入房间的协议确认抽屉文案正确

## 5. 错误提示

- [ ] 页面不再出现“联系开发同学”“接口未部署完整”等工程态文案
- [ ] 连接失败时只展示产品态提示
- [ ] 无明显调试入口暴露给用户

## 6. 云托管建议

当前版本建议优先走“单实例升配”：

- [ ] 保持 1 个稳定在线实例
- [ ] 提高实例 CPU / 内存规格
- [ ] 先观察单实例可承载的房间数和连接数
- [ ] 暂不做多实例横向扩容

说明：
- 当前房间状态依赖单进程内存，直接多实例容易造成房间状态不一致。
- 本版以“尽快稳定上线”为目标，先升配比先改架构更稳。

- [ ] 跑一次 `npm test`
- [ ] 真机至少回归 2 台设备
- [ ] 真机检查分享、重连、结算、退出登录
- [ ] 确认云托管目标、域名、证书都已指向正式环境
