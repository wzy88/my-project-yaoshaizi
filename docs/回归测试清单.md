# 摇骰子小程序：回归测试清单（功能相关）

> 目标：每次改动房间/规则/交互后，用最少时间把“关键链路 + 高风险边界”跑一遍，避免类似「更多菜单 itemList 超 6 项导致打不开」这类平台约束回归。

## 0. 测试前准备

- 环境
  - Node.js 20+
  - 微信开发者工具（建议真机预览/真机调试再跑一遍）
- 启动后端
  - `npm run dev:server`
  - 健康检查：`http://127.0.0.1:3000/health`
  - 小程序 WS：`ws://127.0.0.1:3000/ws`（真机需用局域网 IP 或 WSS 隧道）
- 自动化测试（规则/服务端状态机）
  - `npm test`
- 可选：WS 端到端冒烟（本机可跑，默认跳过）
  - `npm run test:smoke`（或 `DICE_WS_SMOKE=1 npm test`）
  - 若环境禁止测试进程监听端口（报 EPERM），可先手动启动服务，再指定 WS 地址：
    - 终端 A：`npm run dev:server`
    - 终端 B：`DICE_WS_URL=ws://127.0.0.1:3000/ws npm run test:smoke`

## 1. 冒烟（30 秒）

- 能进首页/大厅并连接成功。
- 创建房间成功，房间号正常展示，能邀请另一台设备加入。
- 房主排位面板能打开、能交换座位、能切换叫牌方向（开局前）。
- 房间页右上角「更多」能弹出菜单（注意：微信 `showActionSheet.itemList` 上限 6 项）。

## 2. 房间与会话（创建/加入/离开/旁观）

### 2.1 创建房间

- 进入「创建房间」页面，检查：
  - 显示为固定 8 杯位房间
  - 通配 1 开关可切换
- 点击「创建并进入」
  - 预期：进入房间页，房间状态为 `ready`，房主在座位上。

### 2.2 加入房间

- 第二个设备输入房间号加入
  - 预期：`ready` 阶段加入会直接入座（占座成为对局玩家）。

### 2.3 对局中加入（旁观/等待）

- 在 `rolling/calling/opening/ended` 阶段用第三个设备加入
  - 预期：加入到 `waitingPlayers`（旁观/等待），只能看不能操作。
- 结算后/下一局前，房主打开「音效开关」->「房主工具」->「等待者入座」
  - 预期：可为等待玩家分配 1-8 的空座位；入座后下一局成为对局玩家。
- 房间人数到 8 人后，再加入
  - 预期：拒绝加入（满员不支持旁观）。

### 2.4 离开房间

- 点击「更多」->「离开房间」
  - 预期：断开会话并回到未入房状态；再次进入可重新加入/创建。

## 3. 房主排位（高频改动点）

### 3.1 打开与限制

- 房主在 `ready` 阶段可打开排位。
- 房主在 `ended` 结算后、下一局开始前也可打开排位。
- 非房主、`rolling/calling/opening` 阶段不可排位。

### 3.2 交换/移动（点两次座位）

- 点一个座位（选中）-> 再点另一个座位
  - 预期：
    - 选中的是“有玩家”、目标是“空位” => 玩家移动到空位
    - 两个都是“有玩家” => 交换两人的座位
    - 两个都是“空位” => 仅切换选中态

### 3.3 叫牌方向（顺/逆时针）

- 在排位面板切换「叫牌方向」
  - 预期：房间配置更新成功，开局后锁定不可改。
- 开局后尝试在排位面板切换
  - 预期：提示不可修改（服务端拒绝）。

## 4. 开局与摇骰阶段（rolling）

### 4.1 开始游戏

- 房主点击「开始」
  - 预期：进入 `rolling`，每个对局玩家都可以摇骰（不按顺序），右下角主按钮先显示「摇一摇」。

### 4.2 摇骰次数与锁定

- 单个玩家反复摇骰
  - 预期：最多 5 次，超过提示且服务端拒绝。
- 点击 OK（确认骰面）
  - 预期：锁定后不能再摇；自己座位出现 OK 标记。
- 摇一摇
  - 预期：仅在 rolling 且未 OK 时生效；有节流（不至于连发）。
- 所有人都点击 OK
  - 预期：房间自动进入 `calling`，不再要求房主额外点击“开始叫牌”。

## 5. 叫牌阶段（calling）

### 5.1 行动顺序

- 当前行动玩家高亮正确，顺序按座位 + 方向推进。
- 轮到自己：右下角主按钮隐藏，由叫牌面板接管；面板主操作为「叫点」或（到上限时）「开牌」。
- 未轮到自己：右下角主按钮保留为 disabled 的「等待」，点击无业务响应。

### 5.2 起叫下限、递增与上限

- 第一手叫牌数量 < 起叫最小数量
  - 预期：服务端拒绝并提示原因。
- 递增规则
  - 预期：必须“数量增加”或“数量不变但点数增加”。
- 数量上限
  - 预期：数量不能超过 总骰子数；当达到「上限数量 + 6 点」后，下家只能开牌。

### 5.3 通配 1（万能规则）

- 开启通配 1：未有人叫 1 前
  - 预期：点数统计时 1 可通配到任意点（非 1 点）。
- 一旦有人叫了 1
  - 预期：本局剩余流程中 1 不再通配（只算 1）。

### 5.4 超时自动叫牌/开牌（5 秒）

- 轮到某玩家不操作，等待 5 秒
  - 预期：
    - 有可行的最小合法叫牌：系统替他叫牌并轮到下家
    - 已无可叫（到顶）：系统自动开牌结算

## 6. 开牌与结算（opening/ended）

### 6.1 仅开上一手

- 当前玩家点击「开牌」
  - 预期：只能开上一手叫牌者；不能开自己；结算结果正确。
- 只剩 1 名在线玩家、上一手是自己、上一手叫牌人已不存在时
  - 预期：前端不露出快捷开牌按钮；服务端也不允许非法开牌。

### 6.2 特殊牌型家规

- 顺子算 0（如 1-2-3-4-5）
  - 预期：对任何点数贡献为 0。
- 豹子加 1（如 4-4-4-4-4）
  - 预期：统计该点数时额外 +1。
- 通配 1 有效时，若整手只由被叫点数和 1 组成（如 5-5-5-5-1、5-5-1-1-5）
  - 预期：按该点数的豹子处理，贡献 = `diceCount + 1`；若本局已有人叫过 1，则不再按豹子通配。

### 6.3 输家先手与下一局

- 结算后
  - 预期：输家页面出现「开始」按钮；其他人显示「等待」
- 输家点击开始
  - 预期：进入新一局 `rolling`；骰面清空；上一局信息不再互通（仅历史里可看）。
- 输家离线/已主动退出时
  - 预期：房主可接管点击「开始」；若清理离开玩家后不足 2 人，则回到 `ready`，不强开新局。

## 7. 掉线/重连/离开（高风险边界）

### 7.1 掉线重连

- 在 `rolling/calling/ended` 阶段断网/关闭小程序再回来（30 秒内）
  - 预期：通过 `resumeToken` 重连恢复状态；不会丢房间信息。

### 7.2 主动离开

- 对局中玩家主动点击离开
  - 预期：已经叫过的牌仍有效，骰子仍参与本局统计。
- 如果主动离开的玩家轮到叫牌
  - 预期：服务端快速自动推进，不等待完整超时；有合法叫牌则自动叫，无合法叫牌则自动开。
- 如果主动离开后只剩 1 名有效在线玩家
  - 预期：当前局立即回到 `ready`，不记输赢、不写历史。

### 7.3 临时断线

- 对局中玩家切后台/关闭小程序/网络闪断
  - 预期：按 `resumeToken` 重连恢复；不立即按主动退出处理。
- 轮到临时断线玩家
  - 预期：沿用叫牌超时自动叫牌/开牌。

## 8. 资料与协议（发布前必看）

### 8.1 昵称

- 首次登录后，昵称可在“我的”页修改
  - 预期：1-5 个字符可保存；包含广告、联系方式或违禁词的昵称会被拦截。

### 8.2 协议与帮助

- “隐私政策”“用户协议”“联系邮箱”都能打开或复制
  - 预期：文案与当前版本一致；当前版本不出现聊天/语音说明。

## 9. 平台约束与防坑清单（必看）

- `wx.showActionSheet({ itemList })`：**itemList 最多 6 项**，超过会 fail（表现为“点了没反应/弹不出来”）。
- 真机：不能用 `127.0.0.1/localhost` 连接 WS，需要局域网 IP 或 WSS 隧道。

## 10. 建议的回归执行顺序（最快覆盖）

1) `npm test`
2) 冒烟（更多/创建/加入/排位/开局）
3) 关键链路（rolling -> calling -> open -> restart）
4) 高风险边界（超时自动、主动退出、掉线重连、8 人满员、等待者入座）
