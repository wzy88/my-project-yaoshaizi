本文档只解决一件事：

- 房主常驻入口 `安排座位` 打开后，页面到底怎么设计，才能既承载完整功能，又能和当前房间页风格自然接上。

## 1. 设计目标

这不是普通“表单页”或“后台管理页”，它仍然是游戏房间的一部分。

面板必须同时满足：

1. 看起来像房间舞台的一层控制面，而不是突然跳成业务页
2. 房主一眼能明白自己当前是在：
   - 管理下一局人员
   - 还是正式安排下一局座位
3. 不引入“复杂但不好懂”的拖拽系统，优先采用当前小程序更稳的点选式逻辑
4. 能在不同房间主题下自然适配，不需要重做四套布局

## 2. 总体结构

推荐保留当前 `room-sheet` 体系，继续使用底部弹起的大抽屉，不新开整页。

原因：

- 现在房间主舞台已经建立得比较完整
- 房主操作属于房间内管理动作，不值得跳新页
- 现有 `room-sheet--seating` 已经有结构基础，改造成本最低

统一入口：

- 左上角更多菜单中的 `安排座位`
- 对房主常驻

统一载体：

- `room-sheet room-sheet--owner-manage`

统一大结构：

```text
sheet-head
sheet-mode-banner
sheet-body
sheet-actions
```

## 3. 两种模式

同一个面板，分成两种模式。

### 3.1 模式 A：本局中管理态

触发条件：

- `phase === rolling || calling || opening`

页面目标：

- 房主管理“下局谁上、谁下”
- 不允许改当前局座位和方向

信息层级：

1. 顶部标题
2. 当前模式提示
3. 桌上玩家列表
4. 旁观者列表
5. 底部说明
6. 完成按钮

### 3.2 模式 B：局前排位态

触发条件：

- `phase === ready || ended`

页面目标：

- 房主确认下一局桌上名单
- 调整座位
- 调整顺/逆时针
- 一键完成并开始

信息层级：

1. 顶部标题
2. 当前模式提示
3. 方向切换
4. 自动补位说明
5. 旁观池/待上桌池
6. 8座位排位区
7. 底部操作按钮

## 4. 模式 A：本局中管理态详细设计

## 4.1 顶部

标题：

- 主标题：`房主管理`
- 副标题：`本局进行中`

右上角关闭：

- 保留当前 `完成` pill 按钮风格

模式提示条：

- 文案：`当前只能管理下局人员，本局座位和顺序不会变化`
- 作为一条轻量提示卡放在标题下

## 4.2 桌上玩家列表

每行结构：

```text
[头像] [昵称+座位号] [状态标签] [操作按钮]
```

显示内容：

- 头像
- 昵称
- `X号座`
- 如果是房主，显示 `房主`
- 如果已标记下局旁观，显示 `下局旁观`

按钮规则：

- 默认：`移到旁观`
- 已标记：`取消旁观`

视觉要求：

- 这不是危险删除按钮，不用血红大按钮
- 更像“状态切换芯片”
- 已标记时显著，但不要像立即踢出

## 4.3 旁观者列表

分两组显示更清楚：

1. `待上桌`
2. `旁观中`

每行结构：

```text
[头像] [昵称] [状态标签] [操作按钮]
```

按钮规则：

- `旁观中`：`下局上桌`
- `待上桌`：`取消上桌`

视觉要求：

- `待上桌` 标签是高亮的积极状态
- `旁观中` 标签是低调的中性色

## 4.4 底部说明

固定文案：

- `本局中不能换座位，也不能改顺逆时针；上述变更将在下一局生效。`

为什么一定要放：

- 这是最容易误解的地方
- 必须把“下局生效”说透

## 4.5 底部操作

按钮：

- 主按钮：`完成`

不需要第二个主动作。

因为本模式没有“提交局前排位”的概念，只是录入意图。

## 5. 模式 B：局前排位态详细设计

## 5.1 顶部

标题：

- 主标题：`安排座位`
- 副标题：`下一局开始前统一排位`

右上角：

- `完成`

模式提示条：

- 文案：`系统已自动补空座，你可以继续微调座位与顺序`

这句非常关键，能直接解释为什么玩家一进来已经先落到了某些座位。

## 5.2 方向切换

位置：

- 放在内容区最上方，优先级高于座位网格

形式：

- 两个 segmented controls
  - `顺时针`
  - `逆时针`

理由：

- 房主思考“这局怎么转”时，方向是桌面规则的一部分，不是附属设置

状态：

- 当前选中态明确
- 非选中态弱化

## 5.3 旁观池

局前排位态下，旁观池建议仍然分两组：

1. `待上桌`
2. `旁观中`

但和模式 A 不同的是，这里不再只改意图，而是参与本轮排位。

### 5.3.1 待上桌区

每个待上桌玩家作为一枚可操作卡片/胶囊显示：

```text
[头像] 小王  待入座
```

状态：

- 如果草稿里已经被系统放到座位中，标签显示：`已放入草稿`

### 5.3.2 旁观中区

每个旁观者仍可点击：

- `下局上桌`

但因为本模式就是正式排位态，所以点了之后应直接进入草稿，而不是仅改一个意图。

## 5.4 8座位排位区

这是整个页面核心。

### 5.4.1 不建议拖拽

我建议继续用“点选式换位”，不要做拖拽。

原因：

- 微信小程序里拖拽实现成本高、误触高、回归成本大
- 当前项目已经有点选换位逻辑基础
- 点选更容易做主题统一和状态强调

### 5.4.2 布局形式

仍建议沿用 2 列 x 4 行紧凑 grid，而不是模拟牌桌环形。

原因：

- 环形适合房间主舞台，不适合管理面板
- 面板里最重要的是“清楚管理”，不是“再次还原牌桌”

每个座位卡内容：

```text
1号
房主
```

或

```text
3号
空位
```

### 5.4.3 座位卡状态

至少要有这些状态：

1. 默认占用
2. 默认空位
3. 已选中
4. 目标位
5. 待换出
6. 待换入
7. 待移去旁观

当前现有 `hint-selected / hint-swap / hint-move-out / hint-move-in` 这套思路可以继承，但要扩成更完整的状态语言。

### 5.4.4 交互规则

建议规则如下：

1. 点桌上玩家卡
   - 进入“选中某玩家”态

2. 再点目标座位
   - 空位：移动
   - 已占用：交换

3. 点已选中玩家的“移到旁观”
   - 直接从草稿桌上移出，进入旁观池

4. 点待上桌玩家
   - 如果当前有选中空位，则入座
   - 否则进入“待放置”态，再点空位落座

这个模式下，房主的心智始终是：

- 我在排整桌

而不是：

- 我在处理单个等待者

## 5.5 底部操作区

推荐保留双按钮：

1. 次按钮：`恢复默认补位`
2. 主按钮：`完成安排并开始`

### 5.5.1 `恢复默认补位`

用途：

- 房主改乱了以后，一键回到系统草稿

很重要，因为它能明显降低操作焦虑。

### 5.5.2 `完成安排并开始`

这是局前排位态唯一主 CTA。

按钮禁用条件：

- 桌上在线玩家人数不足开局条件
- 仍有 `pendingSeat` 但没落到桌上
- 草稿数据不完整

## 6. 页面与当前房间风格如何接住

这是这次最重要的 UI 约束。

不能把这个面板做成普通“设置页”。

必须继承当前房间页已有的材质语言：

- 深色底 + 主题高光
- 柔和描边
- 有层次的面板阴影
- 紧凑但不拥挤的卡片体系
- 游戏化的 chip / badge / pill 按钮

### 6.1 可直接复用的现有结构

来自当前页面：

- `room-sheet`
- `sheet-head`
- `sheet-eyebrow`
- `sheet-title`
- `seat-hero`
- `seat-direction-panel`
- `seat-grid`
- `dock-btn`

优先策略：

- 复用已有结构
- 在此基础上新增状态和子区块

### 6.2 不该做的事

- 不要突然变成纯白背景
- 不要用通用 SaaS 卡片表格
- 不要出现和房间主视觉完全不相关的设计语言
- 不要画出代码里根本无从还原的复杂装饰

## 7. 主题适配策略

房主管理面板必须支持：

- jade-green
- ruby-red
- imperial-red
- glacier-blue

但不建议四套独立设计。

正确做法是：

- 一套统一布局
- 一套统一状态系统
- 每个主题只覆盖颜色/高光/描边/按钮态

### 7.1 必须有主题差异的元素

1. 面板底色
2. 面板边框
3. 标题 eyebrow 色
4. 选中态
5. `下局上桌` 积极态
6. `下局旁观` 管理态
7. 主按钮
8. 次按钮

### 7.2 应该尽量统一的元素

1. 间距
2. 卡片尺寸
3. 座位网格
4. 列表结构
5. 按钮位置

## 8. 开发友好的还原原则

为了避免“做出来和设计稿差十万八千里”，页面设计要遵守以下原则：

1. 只画代码能还原的结构
2. 不依赖拖拽、复杂手势、浮动定位特效来承载主功能
3. 所有核心状态都能映射到 class
4. 主视觉变化尽量通过变量控制，而不是写死在某个主题里
5. 交互优先稳定，其次再追求炫

## 9. 最终建议

当前最推荐的页面方案是：

1. 房主入口常驻
2. 同一个面板两种模式
3. 本局中只管“下局生效”的人员意图
4. 局前统一排位，用点选式完成整桌编排
5. 系统先自动补空座，房主只做微调

这套方案兼顾了：

- 功能完整
- 认知清楚
- 研发可还原
- 主题可统一

是目前最适合直接进入研发的一版页面结构。
