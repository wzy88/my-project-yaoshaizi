# 叫牌注意力反馈设计

## 背景

当前 `calling` 阶段的公开信息主要靠玩家座位气泡承载，方向是对的，但在真实聚会场景里，其他玩家不一定能第一时间注意到“刚刚有一手新叫牌已经生效”。

直接增加全量语音朗读会带来两个问题：

- 同桌多人设备同时外放，容易形成回声和噪音
- 体验会重新回到“全局重复播报”，削弱座位气泡作为主信息载体的设计

## 目标

- 让所有在线玩家及时感知到“新叫牌已被接受”
- 叫牌内容仍以玩家座位气泡为主，不增加人声朗读
- 叫牌者本人避免收到重复确认音，减少双响
- 下一位接牌玩家收到更明确但仍轻量的提醒

## 交互方案

### 1. 新叫牌落地

- 仅当服务端确认后的新 `lastCall` 到达客户端时，触发一次注意力反馈
- 注意力反馈由三部分组成：
  - 全房短提示音：轻、短、非语音
  - 最新叫牌气泡脉冲高亮：约 `760ms`
  - 下一位行动玩家轻震动一次

### 2. 叫牌者本人

- 自己点击 `叫点` 后，沿用现有本地确认音/震动
- 服务端回包确认这一手时，不再给叫牌者额外播放全房提示音
- 叫牌者仍可看到自己的叫牌气泡高亮，确保视觉反馈一致

### 3. 边界

- 首次进房同步到已有 `lastCall` 时，不触发这次反馈
- 断线重连后的第一帧房态同步，不补播历史叫牌反馈
- 离开 `calling` 阶段或进入下一局时，清空这类瞬时高亮

## 非目标

- 不增加“7个6”之类的人声朗读
- 不调整叫牌规则、轮转规则、超时逻辑
- 不改变现有语音上传/语音回放链路

## 验收标准

- 新叫牌被接受后，非叫牌者能立即收到一次短提示音
- 最新叫牌气泡出现一次明显但短促的脉冲高亮
- 下一位行动玩家会收到一次轻震动
- 首次进房或重连恢复时，不会对历史叫牌重复播报
- 不影响现有叫牌、开牌、结算流程
