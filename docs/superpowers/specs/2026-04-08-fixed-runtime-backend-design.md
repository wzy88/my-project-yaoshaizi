# 固定运行时后端设计

日期：2026-04-08

## 背景

当前小程序同时支持：

- 微信云托管
- 本地 `ws://` 直连
- 运行时通过页面弹窗填写 `service/env/wsPath`

这套双轨调试能力虽然方便开发联调，但会带来一个明显问题：

- 开发者工具真机预览、体验版扫码、未来正式线上，用户看到的不是同一套产品路径。
- 用户路径里会暴露“配置云托管”“填写服务名”这类只属于开发调试的交互。
- 旧设备缓存里的连接配置还可能继续影响当前包的登录与房间连接。

## 本次调整

本次将产品形态收敛为：

- 用户页面和交互只有一套。
- 后端连接目标由内部运行时配置决定，不由用户在页面中填写。
- 真机预览、体验版、线上版都复用同一套页面结构。

## 实现方案

### 1. 固定运行时连接配置

新增 `miniprogram/utils/runtime-backend-config.js`，统一管理：

- 固定云托管目标
- 固定 WebSocket 目标
- 旧版缓存配置的兼容读取
- 当固定目标生效时，对旧缓存配置做清理

默认仓库里不提交真实云环境，避免把私有配置写死到仓库。

### 2. 连接优先级

运行时连接目标统一按以下顺序解析：

1. 固定运行时配置
2. `App.globalData`
3. 旧版本地缓存（仅兼容老调试数据）

当固定运行时配置存在时，旧缓存不再允许覆盖它。

### 3. 产品页面去调试化

从用户主路径移除：

- 首页“配置云托管”
- 大厅登录浮层“配置云托管”
- “我的”页云托管设置区块

连接异常时，页面只展示产品态提示，不再要求用户手动填写服务名或环境 ID。

## 验收标准

- 真机预览、体验版、线上版使用同一套产品页面。
- 用户不会在首页、大厅、我的页看到云托管配置入口。
- 固定运行时配置生效后，旧缓存不会再把页面切到错误的连接目标。
- 登录与房间连接异常时，只显示产品态错误提示。
