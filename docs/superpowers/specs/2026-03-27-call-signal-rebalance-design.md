# 叫牌信号归位设计

## 背景

当前房间页在 `calling` 阶段同时存在两类叫牌展示：

- 玩家座位旁的叫牌气泡
- 牌桌中央的最新叫牌播报

两者都在表达公开叫牌信息，造成重复感，削弱了“扫全桌读信号”的体验，也让牌桌中央承担了不必要的信息汇总职责。

## 目标

- 去掉牌桌中央的叫牌汇总播报
- 让公开叫牌信息回到玩家座位附近
- 保持“每个玩家都能留下自己的公开信号”
- 自己仍不在座位上显示气泡，但要保留低权重的自我确认
- 不改动叫牌规则、阶段流转和底部主操作语义

## 交互设计

### 1. calling 阶段

- 牌桌中央不再显示最新叫牌播报。
- 非自己玩家只要存在 `currentCall`，就继续在座位附近显示叫牌气泡。
- 这些气泡代表各自已释放的公开信号，不只强调上一手。
- 自己的叫牌不在座位附近显示气泡，避免和自玩家主位区域打架。

### 2. 自己的叫牌确认

- 在底部叫牌区内增加一条低权重文本，用于显示自己的上一手叫牌。
- 建议文案格式：`上一手：7个6`
- 没有自己叫牌时不显示。
- 该文案是确认信息，不承担主引导职责，视觉权重应明显低于主按钮和选择器。

### 3. 中央区域策略

- `ready / rolling / calling / opening / ended` 都不再依赖中央播报承载状态。
- 中央区域尽量留白，把牌桌还原为舞台层。
- 阶段提示继续由底部按钮、底部面板、玩家状态和既有结果区承担。

## 状态与数据约束

- 座位气泡仍基于玩家自己的 `currentCall` 展示。
- 自己的底部确认文案基于自己的 `currentCall` 生成。
- 新一局开始、自己尚未叫牌、或状态清空时，底部确认文案消失。
- 不新增新的历史记录结构，不改变现有 `lastCall` / `callTimeline` 业务数据。

## 非目标

- 不新增叫牌历史列表
- 不修改开牌结果表现
- 不调整叫牌比较规则或超时逻辑
- 不重构玩家座位布局

## 验收标准

- `calling` 阶段牌桌中央不再出现最新叫牌播报 UI。
- 场上已叫牌的其他玩家仍各自保留座位气泡。
- 自己叫牌后，底部出现低权重的 `上一手` 确认文本。
- 新一局或自己尚未叫牌时，不显示该确认文本。
- 不影响现有叫牌与开牌操作流程。
