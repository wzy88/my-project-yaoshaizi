# 房间视觉约定

适用范围：`miniprogram/pages/room/room.*`

这份文档记录当前房间页的视觉与布局期望，后续做 UI 调整时优先遵循这里的约定。

## 1. 总体方向

- 房间是偏游戏化的对局界面，不是通用业务页。
- 目标风格是紧凑、带舞台感、层次明确、操作轻量。
- 保持现有功能和逻辑不变，主要改展示层和空间关系。
- 不再按“组件变小”思路优化，而是按“结构重排”思路优化。

## 2. 核心分层

- 页面分两层：
  - 上层：游戏舞台，承载牌桌、玩家座位、叫牌状态、骰子表现。
  - 下层：功能 UI，承载操作按钮、叫牌控制、辅助信息。
- 游戏舞台是主视觉，功能 UI 只能辅助，不能抢占注意力。
- 底部面板必须更薄、更低、更像 HUD，不要做成厚重面板。

## 3. 牌桌表现

- 牌桌应占据屏幕中上部的大部分空间，作为绝对主舞台。
- 牌桌要有明显的边框和台面层次，像“围桌对局”而不是平铺卡片。
- 桌面边缘要让玩家信息挂在边上，而不是远离桌子单独摆放。
- 参考图里的目标关系是：桌子占主导，玩家围桌贴边。

## 4. 玩家信息展示

- 玩家信息不再做成普通列表或松散卡片。
- 每个玩家信息应是“头像 + 昵称 + 状态”的紧凑竖向卡片。
- 头像是最重要元素，昵称是次级信息，状态气泡是当前回合信息。
- 玩家信息要贴着桌边分布，像围桌座位锚点，而不是漂浮在桌外。
- 当前发言或当前回合的玩家要有明显状态强调，比如高亮、气泡、发光边。

## 5. 自玩家展示

- 自玩家必须比其他玩家更突出。
- 自玩家位置更靠近底部操作区，形成“我在这里操作”的主位感。
- 自玩家头像更大或更醒目，但不能破坏整体座位秩序。
- 自玩家要和其他玩家形成明确视觉区分，不能只是同样卡片放大。
- 自玩家与底部功能区之间要有更强的空间关联。

## 6. 元素间距

- 追求紧凑，但不能拥挤。
- 头像和昵称之间距离要小，整体信息密度要高。
- 玩家卡与桌边的距离要小，形成贴边围桌的感觉。
- 叫牌气泡、头像、昵称之间要避免过大的空隙。
- 中央提示和底部面板之间要留出舞台呼吸感，但不能占太多屏。

## 7. 底部功能面板

- 底部面板现在太厚，需要明显压缩。
- 面板应该更薄、更低，像游戏 HUD，不像大号操作面板。
- calling 态下的叫牌摘要、按钮、选择器都要一起变轻、变紧凑。
- 主按钮仍然要清晰，但不能让整个底栏变得笨重。
- 底部的目标是辅助操作，不是第二个主视觉。

## 8. 信息层级

- 第一层：牌桌和舞台。
- 第二层：玩家座位和当前回合状态。
- 第三层：底部操作 UI。
- 第四层：顶部房间信息和系统状态。
- 任何时候都不能让底部 UI 抢过牌桌和玩家状态。

## 9. 当前调整原则

- 不要再只做字号、按钮大小、卡片尺寸的微调。
- 优先调座位位置、桌边咬合关系、上下层级和底部高度。
- 视觉改造的重点是结构感，不是缩小组件。
- 所有优化都要围绕“更像参考图的游戏房间”展开。

## 10. 已确认的业务约束

- 房间不需要显示分数，分数展示路径保持移除。
- 参考图强调紧凑、游戏化，而不是清爽列表式布局。
- 底部面板需要继续降高，避免占屏过多。
- 不影响当前已实现的功能和逻辑。
- 右下角主按钮的阶段语义固定为：发起者 `开始` -> 全员 `摇一摇` / `OK` -> 非当前叫牌人 `等待` -> 结算后由上一局失败方再次显示 `开始`。
- `calling` 阶段仅当前叫牌人隐藏右下角主按钮并显示叫牌面板；其他玩家保留 disabled 的 `等待` 按钮，不做业务响应。
